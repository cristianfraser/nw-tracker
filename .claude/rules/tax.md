# Tax returns, projections, wealth percentile (nw-tracker)

> Moved verbatim from `AGENTS.md`, whose «Topic rules» index lists the sections of every file under
> `.claude/rules/`. A section named in «…» that is not in this file is in `AGENTS.md` or in the file

## Wealth percentile (/wealth-percentile)

- **Static distribution table, refreshed by hand once or twice a year** (`server/src/wealthDistributions.ts`; procedure in **`docs/wealth-percentile-data-refresh.md`**). Anchors: UBS Global Wealth Databook 2023 (end-2016 → 2022) and UBS GWR 2026 (end-2025). Editions are not comparable, so medians never mix across editions: 2023/2024 are geometric interpolations (`†`); a year without a printed median is calibrated on the Gini table + Millionaire Index (`‡`). The Spanish Latin-America GWR is the only source of per-adult CL/MX/BR levels, kept as printed. `interpolatedRecords()` hardcodes the 2022→2025 pair — generalize it before the end-2026 row.

## Tax return (/tax-return)

- **A local Formulario 22 per año tributario** (`f22/draft.ts`, `f22/payload.ts`, `GET /api/tax-return?tax_year=`, `TaxReturnPage`): filed return, third-party informed figures, and a draft adding what the app knows. Import per year: `server/scripts/import-sii-tax-year.ts --year= --dir=cfraser/sii/AT<year> [--apply]` (migration 198): «F22 Compacto» PDF → `sii_f22_filed` (`siiF22Compacto.ts`, checks 304 = 305, 170 = 158 − 750, 91 = 90 + 39); `DJ_<code>_<year>_<rut>.xlsx` → `sii_informed_dj` (`siiInformedDj.ts`, keyed by column letter + header path).
- **The page is figures, a code list and folded sections (`TaxReturnPage`, `components/tax/`, styles `TaxRows.module.css`; built on the income page's rows and the residency form's fields).** The header picks the year and, for a year with a 1040, the return (F22 / Form 1040, the view buttons); under it the result as four figures (tax filed, draft, difference, the settlement or the 1040's refund / amount owed) and a line of short facts (base, regime, residency). `TaxCodeList` draws both forms' rows under the server's groups (`group`: income, base, tax, result, payment, other; the 1040's income, deductions, tax, payments, result): wide, code, concept, filed, (informed,) draft and difference under a header, a row whose sources agree printing its repeated values quiet; wrapped (container `tax-rows`, the breakpoint stated as the frame's font-size), code, concept, one value and a mark per source that states it, a row whose sources differ adding a line that names each value. A code the draft changes carries a red rule, a third-party figure unlike the filed one an amber rule; «Differences (n)» lists only those. **The server compares, the client picks:** each row's `changed`, `difference`, `informed_mismatch` and `sources_agree` (`f22RowComparison`, `f22/payload.ts`; the 1040's `changed` / `difference`), the payload's `tax_difference`, `changed_codes` / `flagged_codes` (`changed_lines`) and `dividends_gross_clp`. A payslip's withholding row carries its own `differs` (`payrollWithholdingMonths`, the year rule's test). Every detail section (`TaxSection`) is folded under a heading with its line count and headline figure, a problem in red (an unlinked settlement, pending dividend detail, a withholding difference, an unused loss); its rows are a `TaxDetailList` (wide: columns; wrapped: (lead,) name and the headline figure, the other figures named on wrapped lines; 15 rows, then more on request), a W-2 label / amount pairs. The prose that headed the page (base, residency, the legal assumption) is the «Residency and basis» section; the loss-offset hints are one «Loss offset» section; the 1040's notes one «Readings and what is not modelled» section. A count picks its `…One` key at 1 (`countLabel`, both keys named at the call: the dead-key test reads literals).
- **One set of tax-year facts; returns map them (`server/src/taxFacts/`, `server/src/f22/`; docs/demo-app-features-plan.md §5 items 13, 15).** `taxFacts/` states what happened in a `DateWindow`, in its own currency, with source, and nothing a law decides: `dividendFacts`, `interestFacts`, `equityAccountDisposalFacts` / `cryptoDisposalFacts` / `fundDisposalFacts` (lot-walk disposals in trading currency; lot method is the caller's), `rentalFacts`, `loanPaymentFacts`, `chileanPayslipFacts` / `usPayStubFacts` / `feeReceiptFacts`, `fundHoldingFacts`. Income source is `taxFacts/payers.ts` alone (`FOREIGN_BROKER_COUNTRY`, other brokers Chilean; `US_BANK_ISSUERS`; read from `broker_cash` roles and `bank_account_numbers`). No conversion, reajuste or code there. F22 blocks under `f22/` (`salary`, `fees`, `rentals`, `art107`, `crypto`, `foreignShares`, `foreignIncome`, `dividends`, `foreignFx` (F22-only), `estimates`) apply Chilean rules; `blocks.ts` reads a window's blocks, `resident.ts` / `nonresident.ts` regimes, `chain.ts` arithmetic, `sources.ts` filed form + DJs, `offsets.ts` pools, `draft.ts` composes. A new reader of tax-year ledger data adds a fact, never SQL in a return. Refactor parity: `server/scripts/capture-tax-payloads.ts` before/after, byte-identical.
- **Fees from boletas issued; lender interest through the cap (migration 296).** With no filed form, the fees box comes from `sii_issued_fee_receipts`: 547 gross, 494 presumed expenses (30 %, ≤ 15 UTA), 770 APV régimen B when no employer reported the year (no DJ 1887; else 765), 110 = 547 − 494 − 770, 198 retention credit; a boletas-only year has base `fees`; fees add to an informed/payroll base. - **Every año tributario has a tab:** `availableF22TaxYears` (AT2017 → next April's) plus older filed years. Flagged `estimated` («≈»). Open: the lender's reported 2024 interest disagrees with the ledger.

- **Foreign currency is tax lots on one walk shared by the card rate and the tax (`foreignCashLotWalk.ts`, `foreignCashTaxLotEvents.ts`, `f22/foreignFx.ts`, `bcentralObservado.ts`; `docs/tax-usd-lots-plan.md`, docs/any-currency-plan.md C2).** One FIFO slice queue per foreign cash account in its `cash_currency` (integer minor units, `currencyMinorDigits`), keeping original date and cost (Oficio 233/2018: FIFO or LIFO, never average), with request-time reservation of broker withdrawals, own transfers carrying slices intact (same currency only) and caller-priced inflows. **A conversion between two foreign currencies** disposes of the first (`convertedTo`, nothing carried) and acquires the second (source `conversion`): the cost tracer carries the consumed slices' pesos; the tax module prices the new lot at its own observado and realizes the old under 2573 and 2390 (deferred under `none`). ## Projections (/projections)

- `GET /api/projections` (`server/src/projections.ts`, pure `runProjectionEngine`): one **real** (today's-money) trajectory in the display unit — accumulation to 65 (born 1992-01 → 2057-01; invested compounds monthly + aporte, RE/cash flat real), then three drawdown strategies over the **drawdown pot** = invested + `liquidate_other_pct`% of the rest (default 0, FIRE framing) to `end_age`. `monthly_rent` adds passive income to every strategy; the fixed-income strategy funds only `target − rent` (SWR fixed-real %, % of balance, fixed real income; depletion ages in `summary`). Invested trajectory = `proj_invested`. Nominal line = real path × the unit's inflation (`inflation_pct[unit]`, query `inflation_<code>_pct`, defaults `PROJECTION_INFLATION_DEFAULT_PCT`: CLP 3,5 %, USD 2,5 %, EUR 2,0 %, served as `inflation_default_pct`; a core currency without a default throws) — all units share one trajectory. Money inputs (`monthly_aporte`, `monthly_income`, `monthly_rent`) are in `<key>_currency` (default the unit), converted at today's stored rate (`projectionParamsFromQuery`), echoed in the unit. Defaults: aporte = trailing-24m personal deposits into retirement+brokerage; base = last `getDashboardOverviewBlock` point; params bounded (`ProjectionParamError` → 400). USD milestones (250k–2M) as constant reference columns at today's stored rate.
- Client `ProjectionsPage` (`/projections`, nav link seeded by `seedNavTree`): inputs show server-resolved params; overrides persist in localStorage `nw-tracker.projections.overrides.v2` as changed query params (money inputs with their currency; old `nw-tracker.projections.overrides` migrated once by `projectionsOverrides.ts`; empty = default; Restablecer clears); unit follows the global unit; AppLineChart with dashed reference lines.
