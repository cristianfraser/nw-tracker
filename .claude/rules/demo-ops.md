## Hosted demo (Render)

Single Render web service (**`render.yaml`**) serving synthetic data, open and read-only; everything env-gated.

- **Release branch `demo`** (`scripts/release-demo.sh`, `npm run release:demo [-- <sha> | --yes | --rollback <sha>]`): Render builds only `demo` (`render.yaml` `branch: demo`; Blueprint linked to it, so `render.yaml` changes wait for a release). The script fast-forwards `demo` to a commit on `origin/main` (tip by default), lists and asks; refuses non-`main` commits, non-fast-forwards (`--rollback` moves back with a lease) and a dirty tree. Never push `demo` by hand or unasked — releasing is the user's call (the repo is public; `demo` only carries published `main` commits).
- **`DEMO_MODE=1`** (`server/src/demoMode.ts`): requires `NW_TRACKER_TEST_DB` pointing at a dedicated file (throws otherwise — never the real DB); an empty DB is filled at boot (`loadDemoRealMarket(demoMarketSpec())` + `generateDemoDb({ person: DEMO_PERSON, market: "real" })` = `generate-demo-data.ts --real-market`). **On Render the build generates it** (`npm run demo:generate -w nw-tracker-server` ending `buildCommand`): the persistent disk means Render stops the old instance before booting the new one (no zero-downtime; «Restart service» starts the latest build), so fetching at boot is downtime, while a failed build leaves the old version serving. Demo defaults: `DB_BACKUP_ENABLED=0`, `GLOBAL_SYNC_ENABLED` / `LIVE_QUOTES_SYNC_ENABLED` / `USAGE_LOG_ENABLED=1`; warmer on.
- **Real market data** (`demoData/demoRealMarket.ts`, `demoMarketActivity.ts`): Yahoo closes of `DEMO_TICKERS` (BTC-USD included) into `equity_daily`; `.SN` tickers from the committed Bolsa snapshot `server/data/demo/santiago-closes.csv` plus Yahoo bars after it (Yahoo lacks history for thin Santiago tickers and Render gets HTML from the Bolsa API; refresh with `npm run demo:refresh-santiago-snapshot -w nw-tracker-server` from a machine that reaches it; a snapshot older than `DEMO_SANTIAGO_SNAPSHOT_MAX_AGE_DAYS` = 7 is refused; `equityBolsaSantiagoEod.ts` stays in `src` for it); every `equity_with_dividends` benchmark ticker with its `equity_dividends` (else the benchmark row reads «—»); CLP=X; Banco Central dollar, euro, UF, UTM, IPC (`BCENTRAL_EMAIL` / `BCENTRAL_PASSWORD`, Render secrets `sync: false`; required). History to yesterday (crypto: last completed UTC day). Each source retries ~10 min (`DEMO_MARKET_RETRY_DELAYS_MS`) then fails the build. Unit math reads stored closes (`dbMarketReader`). **AFP** (`afpUnoApi.ts`, `loadDemoPensionMarket`): «Modelo-A» (`afp_modelo_cuota_a`) switched into «UNO-A» (`afp_uno_cuota_a`) at `AFP_SWITCH_MONTH` (an `afp_fund_switch` with both cuota counts). The SP refuses Render, so Modelo uses a committed snapshot (`server/data/demo/afp-modelo-fund-a-2018-2020.csv`, `parseDemoAfpModeloCsv`) and UNO its own API (`POST https://www.uno.cl/api/valor-cuota-buscar/historico`, `{fechaInicio, fechaFin}`; newest first, decimal comma, one row per calendar day, full history from 2019-10-01; `codigo` ≠ "0" throws — `parseUnoValorCuotaHistorico`), both into `pension_fund_unit_official`. `afpUnoOfficialSource()` (`afpUnoOfficialSync.ts`) is `uno_api` under `DEMO_MODE`, `sp` otherwise — the one choice point; it picks the runner (`syncAfpUnoFromUnoApi` re-reads 60 days back) and adds `AFP_UNO_SOURCE_EXTRA_LAG_BUSINESS_DAYS` (UNO publishes a business day after the SP). **AFC** is a synthetic book account (`afc_cic` «Not configured»), marked each Chile business day at ~3,5 %/yr (`writeAfc`, `demoData/generate.ts`). **Syncs run only while someone browses:** real visitor requests (bots never) note activity; global sync and live quotes skip ticks while asleep and run on wake (`onDemoMarketWake`); sleep after 30 min idle (`DEMO_MARKET_IDLE_MS`). Author-only sources (`DEMO_SYNC_DISABLED_SOURCES`: Fintual goals, official-serie check, Risky Norris composition, CMF filing) never poll or dim, and are not listed: `syncStatusPayload` leaves out what the deployment profile disables, and a run logs no «skip» line for them. A `fund_unit` benchmark is offered only while its series has values on file (`benchmarkFundSeriesHasData`), so «Risky Norris» is not in the demo's benchmark picker; the ticker's `risky_norris` / `risky_norris_proxy` fields are null there (no series, no chip). `demoModeEnabled` lives in leaf `demoModeFlag.ts`. Rehearsal: `server-demo` / `client-demo` with the Banco Central values set.
- **The home server publishes the demo's market; Render downloads it** (`demoData/demoMarketArtifact.ts`, `demoMarketRelease.ts`, `demoMarketPublishJob.ts`, `scripts/publish-demo-market.ts`, `docs/demo-market-publish-plan.md`). Nightly at 01:00 Chile (and at boot when the last success is >20 h old) the primary runs the loader in a child process on a scratch DB (`server/data/demo-market-publish.db`; never the live one — the loader writes through the process `db`), Santiago from the Bolsa (`{santiago: "bolsa"}`), exports `DEMO_MARKET_TABLES` (fails if any other table moved, `assertOnlyMarketTablesChanged`) as gzipped JSON (`schema_version`, `generated_at`, `complete_through`, spec, columns/rows) to the fixed release `demo-market` (`demo-market.json.gz` + `demo-market.meta.json`; upload as `.next`, delete, rename; never the latest release). Needs `DEMO_MARKET_PUBLISH_TOKEN` (fine-grained, Contents read/write) and `DEMO_MARKET_PUBLISH_ENABLED` (default on, off with `BACKGROUND_JOBS_ENABLED=0`, never on the demo); failure = notification, retried after 15 and 45 min. Optional, off: `NW_DEPLOY_RELEASE_DEMO=1` + `RELEASE_DEMO_PUSH_REMOTE` in the deploy plist release each healthy deploy (`release_demo_after_deploy`).
- **Synthetic databases are a person told through documents** (`server/src/demoData/`, `docs/demo-generator-plan.md`). `person.ts` holds `DEMO_PERSON` (the demo's hand-tuned story; no personal data) and `testPerson(today)` (Vitest: ~20 months, contrato then contractor job, rented flat, Santander + BCI cards with cuotas, SPY + one play, a Fintual-style fund, AFP, AFC, APV — short for speed). `simulate.ts`: day-dated events from seeded per-month streams (`rng.ts`: adding a month never moves a past one), balances in calendar order, never negative; two cash bands (`CHECKING_BAND` / `SAVINGS_BAND`): checking keeps 1–2 months of trailing expenses (topped to 1,5 from savings at payday, trimmed above), the cushion (3–6 months + the next six months' known needs: cash car, December APV, pie, move-in, gap month) sits in `Person.savings` (a money-market fondo «Fondo Mutuo Money Market», series `demo_fm_money_market`, term-deposit curve − 0,3 %; the DAP principal comes from it), a need moves to checking at the prior month's payday, the excess goes to the broker; with no savings vehicle (Vitest) the savings band sits on checking; lifestyle ratchets toward a concave function of smoothed income. `render.ts` produces documents and `generate.ts` imports them through the real functions: cartolas (`applyBankAccountStatements`; own-account transfers written first so the cartola row is kept as the transfer), the current checking listing (`applyBankAccountMovements`), card facturaciones in both currencies as canonical statements (`applyCanonicalCardStatements`) + the open cycle (`importCcListingLines`), `convertCcPaymentMirrors`, Previred parameters and liquidaciones (`applyPayrollParameters`, `applyEmploymentPayslips`). Written directly: the dollar checking account, broker/exchange ledgers, AFP cuota ledger (Modelo → UNO), AFC/APV/money-market book marks (cartola «TRANSF A AGF ANDES FM MONEY MARKET» / «RESCATE …» rows kept as transfers), contractor payslips (USD, `origin = 'rebuilt'`, no deposit link — wires land in the dollar account), the mortgage ledger, the official IPC from the UF. Contractor years: boleta self-retention paid by F29 monthly, April F22 settles IGC net of independent contributions (credited to the AFP in July); APV goes régimen B when the marginal rate passes 15 %. **April is the tax module's** (`taxDocuments.ts`): the generator writes the year's documents (`sii_issued_fee_receipts`; `movement_dividend_details` with 15 % US withholding; in March DJ 1887 from liquidaciones via `payrollTaxYear`, DJ 1899 APV-B, DJ 1898 via `mortgageInterestForYear`), then `buildF22Draft`'s 305 plus code 900 (fee contributions, not drafted) is the settlement. It re-simulates from a checkpoint (`saveDemoPristineCopy` / `resetDemoDatabaseToPristine` on `<db>.pretax`) feeding `simulate(…, { aprilSettlements })` until every settlement matches (`MAX_TAX_PASSES` 6), then stores each past return as filed (`sii_f22_filed`) linked to its movement (`f22_settlements`). The simulator's own estimate only seeds pass 1 and picks the APV regime. The tax page shows on the demo. `invariants.ts` fails the build on balance mismatches vs the story, a cartola account below zero, an unpaired payslip or card payment, or net worth >25 % from US$400k.

## Usage and performance log (migration 247, `usageLog.ts`, `usageReport.ts`, `usageDb.ts`, `/panel/usage`)

- **Recorded so optimization follows real use** (primary and demo). Every `/api` request (`usageLogMiddleware`, mounted first): duration to last byte, status, pre-compression size (the request context's `jsonBodyBytes`, set by `jsonResponse.ts`, else `Content-Length`; none for 304), cache outcome (`requestCacheStats.ts` per-request `AsyncLocalStorage`; `getAggregationCached` reports each lookup: warm = all hits, cold = any miss, neither = none). Aggregated per UTC hour × method × route pattern (`req.baseUrl + req.route.path`, `(unmatched)` for 404) × work-changing params (`USAGE_KEY_QUERY_PARAMS`: `unit`, `days`, `period`, `portfolio_group`, …; never `account_id` or free text) into `usage_endpoint_hourly` (count, total/max ms, 4xx/5xx, bytes, warm/cold, 15-bucket histogram `USAGE_HISTOGRAM_BOUNDS_MS`, `h00..h14`, for p50/p95). Every route change (`useUsagePageTiming`, `client/src/usagePageTiming.ts`, beacon `POST /api/usage/page-view`, untimed) into `usage_page_views`: path, route (numeric segments → `:id`), first-page flag, settle time (route change, or page start for the first, to the last query fetch once 400 ms quiet; left/hidden/still fetching after 60 s = no time, `outcome`). Only the path is stored (plus the daily `visitor` hash on the demo).
- **Requests only touch memory:** flushed once a minute in one transaction (`flushUsageLog`, upserting the hour); endpoint rows >90 days deleted daily; page views kept.
- **Where:** `usageDb()` — main DB on the personal instance, `DEMO_ANALYTICS_DB` on the demo. `USAGE_LOG_ENABLED` (default on) defaults to 0 under `BACKGROUND_JOBS_ENABLED=0` so dev servers never write the primary's DB; the demo defaults it to 1. When off, the beacon answers 204.
- **`/panel/usage`** (`GET /api/usage/report?days=1|7|30|90`, `GET /api/usage/endpoint-trend?method=&route=&params=&days=`): top pages (views, exact settle p50/p95/max, unsettled views, mean queries), endpoints by p95 (count, p50/p95/max, total time, warm share, errors, mean size), and a picked endpoint's daily trend over every Chile day. The server computes all figures. Demo: 404 `usage_report_not_public` (use `npm run demo:visits`).

## Dashboard performance profiling

- **`npm run profile:dashboard`** (from `server/`): sequential builder timings on the test/dev DB (`NW_TRACKER_TEST_DB` or `server/data/nw-tracker.test.db`).
- **`DEBUG_PERF=1`** (or `DEBUG_VERBOSE=1`) logs `[heavy]` spans during requests.
- **`GET /api/dashboard/page-bundle`**: the home page's one call, served from `dashboard.page_bundle|<unit>` (built by the warmer; the cached value is the in-flight promise so concurrent cold requests share a build). Dropped by every applied change of the change log (`cacheRegistry.ts`, family `home_bundle`) and by `invalidateMarketDataAggregations`; only requests in an invalidation→rewarm gap pay the build.
- **`GET /api/dashboard/nav-context`** (sidebar/group pages): account rows, card metrics, value map, no net-worth series; fetched on group/liabilities routes and account pages whose nav node has routable children (home uses the bundle). **Scoped** by required `?root=<nav node slug>` (`navContextScope.ts`): card metrics of the subtree and of groups its nodes host (`linked_card_slugs`), the account rows those nodes hold plus every liability account (the property card names the mortgage), the value map under the node; bucket totals, layout and liabilities breakdown whole. The Pasivos tree is searched first (net worth has a childless `liabilities` node). The client keys on the root and merges into the stored nav snapshot (`mergeNavContextIntoSnapshotCache`; never writes without one — a slice doesn't cover the tree); the warmer builds visited group pages' slices. It is requested beside the page's own requests and the strip shows as soon as it lands, dimmed until then.
- The dominant cost is usually the portfolio-group totals inside **`getDashboardValuationTimeseries`** / **`getGroupValuationTimeseries`** (`@heavy` in source).
- **JSON is serialized once and compressed** (`jsonResponse.ts`): `jsonResponseMiddleware` replaces `res.json` on `/api` with the same body, `Content-Type` and weak ETag (over uncompressed bytes, so 304s work across encodings); bodies ≥1 KB get `Vary: Accept-Encoding` and brotli (preferred on q ties; browsers offer it on HTTPS only) or gzip, never over an existing `Content-Encoding` or `no-transform`. A payload marked with `markJsonResponseCacheable` keeps bytes, ETag and compressed forms in a WeakMap keyed by the object (lives and dies with the cache entry). Marked: group and account daily-series responses (`groupDailySeriesResponse.ts`; account as `daily.series|response|account|`, dropped by API writes), the group pages' cached responses (`groupPagePayloads.ts`, family `group_responses`), the page bundle, nav snapshot/context, the account detail bundle, both card ledgers. **Only immutable cached objects may be marked** (a mutated object serves stale bytes); others are stringified per response at gzip 1 / brotli 1 (cached ones gzip 6 / brotli 5, once per build).
